# MaternaLink product site (static)

Rebuild of the MaternaLink prototype's public site to the Vytalix standard: eight pages, one stylesheet, three scripts, no build step, no external JavaScript. Brand: Vytalix Blue (#153892) with a rose accent inherited from the original MaternaLink heart.

## Pages
`index.html` (bilingual EN/FR landing), `platform.html`, `programmes.html`, `security.html`, `pricing.html`, `pilot.html` (request form), `login.html` (operator access, demo), `dashboard.html` (demo operator dashboard with synthetic data: patients with nested newborns, escalation queue with assign/contact/outcome, patient record with overview, blood-pressure trend, timeline, notes and voice diaries, analytics, admin).

## Regenerating pages
Page bodies live in `_pages.py`; the shared header, nav, footer and metadata live in `_shell.py`. After editing either, run `python3 maternalink-site/_shell.py`. The generated HTML is committed, so deployment needs nothing but the folder.

## Language
`assets/js/i18n.js` holds English and French strings for the landing page (`data-i18n` keys). French is a working translation and needs a professional review before launch. Yoruba, Hausa, Igbo and Pidgin are roadmap items.

## What was deliberately changed from the prototype
- Product name standardised to **MaternaLink**; "by Vytalix" lock-up with the real mark.
- Claims aligned to `/FACTS_BASE.md`: "in development", "not a medical device", "not yet assessed"; the prototype's "risk engine (rules and AI)" and "suggested actions" are presented as **programme-configured escalation rules for human review**, with no clinical recommendations generated by the software.
- Synthetic demo data only; no photographs of identifiable people; phone numbers masked.
- A pricing page derived from `/docs/21_MATERNALINK_PRICING.md`.
- Accessibility: skip link, focus states, ARIA on tabs and navigation, WCAG AA contrast, reduced-motion respected, dark theme.

## Deploy
Any static host (Netlify, Vercel, GitHub Pages): publish the `maternalink-site` folder. Before launch: replace the placeholder domain in metadata, wire `pilot.html`'s form `action` to Formspree/Netlify Forms/CRM, add the legal entity to the footer, and put the real operator application behind authentication (this site's login and dashboard are demos).

## Pre-launch checklist
1. Entity incorporated and IP agreement signed (see `/docs/00_MASTER_AUDIT.md`).
2. Intended-use statement reviewed by a clinician and a solicitor; copy re-checked against it.
3. French reviewed; translations for additional languages commissioned only after content sign-off.
4. Form endpoint connected and tested; no patient data accepted through the form.
5. Link check (script in this README's history) and accessibility pass.
